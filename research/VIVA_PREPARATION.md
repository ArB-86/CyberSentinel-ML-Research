# Mid-viva preparation: model comparison and research defence

Use the answers below as a concise speaking guide. Replace any bracketed result with a value generated by the experiment harness. Do not quote planned or literature results as if they were produced by CyberSentinel.

## Q1. Why did you initially choose Isolation Forest?

Isolation Forest is an unsupervised anomaly detector that isolates observations through random feature splits. Anomalies often have shorter isolation paths. It supports benign-only training and uses sub-sampling, which is attractive for large, high-dimensional network-flow data. The original method is described by Liu, Ting and Zhou (2008), DOI 10.1109/ICDM.2008.17.

## Q2. Why was using only Isolation Forest not sufficient?

Choosing one algorithm without evaluating alternatives does not establish that it is the best fit for the dataset. Different detectors capture different structures: Isolation Forest uses isolation, LOF uses local density and One-Class SVM estimates a boundary around normal traffic. We therefore added a controlled comparison rather than claiming the original choice was universally optimal.

## Q3. Which models did you compare, and why?

- Isolation Forest: existing unsupervised baseline.
- LOF: checks whether local density deviations identify suspicious flows that a global isolation method misses.
- RBF One-Class SVM: checks a nonlinear boundary around benign traffic.
- Random Forest: a separate supervised reference to show what is possible when attack labels are available during fitting.

Random Forest is not presented as an equivalent unsupervised model.

## Q4. Did you train the models or only compare papers?

We trained Isolation Forest, LOF and RBF One-Class SVM under a shared benign-only protocol on verified CICIDS2017 data across three seeds. The measured outputs are documented in EXPERIMENT_RESULTS.md. The earlier Isolation Forest notebook metrics are historical results under a different split and threshold-selection protocol, so they are reported separately.

## Q5. How did you avoid using attack labels to train unsupervised models?

The Isolation Forest, LOF and One-Class SVM fit only on benign training records. The `Label` column is removed from the feature matrix. Labels are retained separately for split stratification and final evaluation. A held-out benign-only validation sample sets the alert threshold; attack labels are not used to optimise the unsupervised threshold.

## Q6. Why not use accuracy alone?

The dataset is imbalanced: the original notebook reports about 84.91% benign and 15.09% attack flows. A detector can achieve apparently high accuracy by predicting mostly benign. We therefore report PR-AUC / Average Precision, attack precision, recall, F1, FPR, FNR, balanced accuracy, MCC and per-attack recall. PR-AUC is especially informative for the minority attack class.

## Q7. How was the threshold selected?

All detectors produce continuous scores. We orient scores so higher means more anomalous, then take the upper 5% tail of a held-out benign-only calibration sample. This targets the same nominal false-positive budget across models. We then freeze the threshold and evaluate on the test sample. The observed test FPR can differ from 5%.

## Q8. Why did you use LOF novelty mode?

Default LOF is designed for outlier detection on the fitted sample. We need to score new unseen test flows, so we set `novelty=True`. Scikit-learn's documentation warns that novelty-mode scoring methods should be applied to unseen observations, not the training observations.

## Q9. Why is One-Class SVM computationally expensive?

Kernel One-Class SVM relies on pairwise kernel relationships and scales much less comfortably with sample count than Isolation Forest. We cap the common benign training sample and explicitly report sample counts and runtime. The cap is a computational constraint, not evidence that the method is intrinsically worse.

## Q10. How did you address duplicate-data leakage?

The new split hashes numeric feature vectors without labels and uses StratifiedGroupKFold so exact duplicates cannot cross train, validation and test. A 2026 CIC-IDS2017 study reports material exact-duplicate overlap in its own record-level split, motivating this control. Our split does not eliminate five-tuple or temporal overlap because the cleaned Parquet lacks IPs, ports and timestamps.

## Q11. What are the limitations?

CICIDS2017 is a controlled benchmark with class imbalance and repeated flow patterns. Very rare classes have tiny support, so per-attack recall can be unstable. The cleaned dataset has no connection identifiers for group splitting. The experiment uses a bounded common sample for LOF and One-Class SVM, so runtime and train-row counts must be disclosed. Results on one dataset do not prove production generalisation.

## Q12. How will you decide which model is best?

There is no model winner declared in advance. We compare ranking quality (PR-AUC and ROC-AUC), detection at the fixed false-alert budget (precision, recall, F1, FPR), rare attack coverage and computational cost. The final recommendation depends on the project's operational trade-off: missed attacks versus analyst alert burden and runtime.

## Q13. What does the existing Isolation Forest score mean?

The repository notebook reports a held-out test ROC-AUC of 0.8862, PR-AUC of 0.6801, attack precision of 0.6386, recall of 0.7250, F1 of 0.6791 and FPR of 0.0729. These are historical notebook outputs from a row-wise random split with a validation threshold selected by attack F1. They must not be compared as if they came from the new duplicate-grouped, benign-calibrated protocol.

## One-minute summary

"We selected Isolation Forest initially because it is an efficient unsupervised method suitable for large flow datasets. The panel correctly asked whether that choice had been compared with alternatives. We addressed this by designing an algorithm-level study with LOF and One-Class SVM, which model local density and normal-data boundaries, respectively. We fit all unsupervised models on benign traffic only, keep exact duplicate feature vectors within one split, calibrate thresholds on held-out benign validation data to a common false-positive target, and report PR-AUC, attack recall, F1, false-positive rate, per-attack coverage and runtime. Random Forest is presented separately as a supervised reference. In the three-seed pilot, RBF One-Class SVM achieved the strongest mean PR-AUC and F1 among the unsupervised models. We describe it as the strongest candidate in this bounded pilot, not as a proven production winner."
